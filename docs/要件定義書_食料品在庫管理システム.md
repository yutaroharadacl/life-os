# 要件定義書：家庭用食料品在庫管理システム

- 作成日：2026年8月5日
- バージョン：v1.0

---

## 1. 背景・目的

以下の課題を解決するために、家庭内の食料品在庫を「見える化」し、消費期限を管理できるシステムを構築する。

- 賞味期限切れによる食品廃棄が発生しており、削減したい
- 買い物時に在庫を把握しておらず、同じ食品を二重に購入してしまうことがある
- 家族間で在庫状況が共有されておらず、誰が何を持っているか分からない

---

## 2. システム概要

家庭にある食料品の在庫状況（品目・数量・消費期限など）を登録・確認でき、消費期限が近づいた際に通知してくれるシステム。
初期フェーズでは手入力による登録を基本とし、将来的にはレシート読み取りやバーコードスキャン等による自動登録機能の追加を目指す。

---

## 3. スコープ（対象範囲）

### フェーズ1（今回のスコープ）

- 食料品の手入力による在庫登録・編集・削除
- 消費期限（または経過日数）の管理・通知
- 在庫一覧の閲覧
- カテゴリ・保管場所のマスタ管理
- 単一ユーザーでの利用を前提とする（ログインなし）

### フェーズ2（将来のスコープ／今回は対象外）

- レシート読み取りによる自動登録
- バーコードスキャンによる自動登録
- 家族間でのデータ共有（複数ユーザー対応）
- アカウント管理機能（ログイン、世帯単位のデータ分離）

---

## 4. 利用者

- **主な利用者**：家庭で食料品を管理する人（単一ユーザー、フェーズ1）
- **利用デバイス**：スマートフォンを主に想定。PC（Webブラウザ）でも利用できることが望ましい
- **利用シーン**：
  - 買い物前：家に何があるか確認したい
  - 買い物後：買ってきたものを登録したい
  - 日常的に：消費期限が近い食品を確認したい

---

## 5. 機能要件

### 5-1. 在庫登録機能

- 食品名、数量、期限（任意）、購入日、カテゴリ、保管場所、メモを入力して登録できる
- カテゴリ・保管場所はそれぞれのマスタから選択する

### 5-2. カテゴリマスター管理機能

- 初期状態でいくつかのカテゴリが用意されている（例：野菜、肉、魚、乳製品、調味料、冷凍食品など）
- ユーザーが独自にカテゴリを追加・編集・削除できる

### 5-3. 保管場所マスター管理機能

- 初期値：冷蔵庫、冷凍庫、パントリー、常温棚 など
- ユーザーが独自に保管場所を追加・編集・削除できる
- 粒度は「冷蔵庫」「冷凍庫」など大枠でよい（野菜室・チルド室のような細分化はしない）

### 5-4. 在庫一覧・検索機能

- 登録済みの食品を一覧表示できる
- カテゴリ・保管場所・キーワードで検索・絞り込みができる
- 消費期限が近い順に並び替えできる
- 期限が設定されている食品は「期限までの日数」を表示
- 期限が未設定の食品は「購入日からの経過日数」を表示

### 5-5. 在庫編集・削除機能

- 数量の増減を編集できる
- 保管場所を変更できる（例：冷蔵庫→冷凍庫へ移動）
- 使い切った・廃棄した食品を削除できる

### 5-6. 消費期限管理・通知機能

- 消費期限が近づいたらプッシュ通知で知らせる
- 通知タイミングはアプリ全体で一律設定（例：「◯日前」をユーザーが数値で設定可能）
- 個別（食品ごと）の通知設定はフェーズ2の拡張候補とする
- 期限切れの食品は一覧上で警告表示（例：赤色）する

---

## 6. データ要件

### 食品在庫データ

| 項目     | 説明                                                      |
| -------- | --------------------------------------------------------- |
| 食品ID   | データを一意に識別するID                                  |
| 食品名   | 例：牛乳、にんじん                                        |
| カテゴリ | カテゴリマスターと紐付け                                  |
| 保管場所 | 保管場所マスターと紐付け                                  |
| 数量     | 個数・本数など                                            |
| 期限     | 任意入力。消費期限・賞味期限を区別せず1つの項目として管理 |
| 購入日   | 期限未設定の食品の経過日数把握に使用                      |
| 登録日   | システムに登録した日時                                    |
| メモ     | 任意の備考欄                                              |

### カテゴリマスター

- カテゴリID、カテゴリ名

### 保管場所マスター

- 保管場所ID、保管場所名

---

## 7. 非機能要件

| 項目               | 内容                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| セキュリティ       | フェーズ1はログイン機能なし。フェーズ2でアカウント管理（ID/パスワード認証、世帯単位のデータ分離）を追加 |
| 性能               | 在庫件数は数十〜数百件規模を想定し、その範囲でストレスなく動作すること                                  |
| 可用性             | 特別な要件なし（一般的なWebサービス/アプリレベルで十分）                                                |
| ユーザビリティ     | スマホでの片手操作・簡単な入力ができること。入力項目は極力シンプルにする                                |
| マルチデバイス対応 | スマートフォンを主とし、PCブラウザからも利用可能にする                                                  |

---

## 8. 画面要件

| No  | 画面名                 | 概要                                                                  |
| --- | ---------------------- | --------------------------------------------------------------------- |
| 1   | 在庫一覧画面（ホーム） | 登録済み食品の一覧表示（カテゴリ/保管場所での絞り込み、期限順ソート） |
| 2   | 食品登録画面           | 食品名、カテゴリ、保管場所、数量、期限、購入日、メモを入力            |
| 3   | 食品編集画面           | 数量・保管場所・期限などを編集                                        |
| 4   | マスタ管理画面         | カテゴリ管理・保管場所管理など、各種マスタデータへの入り口（一覧）    |
| 4-1 | 　└ カテゴリ管理画面   | カテゴリの追加・編集・削除                                            |
| 4-2 | 　└ 保管場所管理画面   | 保管場所の追加・編集・削除                                            |
| 5   | 通知設定画面           | プッシュ通知のタイミング（◯日前）を設定                               |

**設計方針**：カテゴリ・保管場所以外にも今後マスタ（例：単位マスタ、よく買う食品リストなど）が増える可能性があるため、「マスタ管理画面」を上位概念として設け、同じ枠組みで拡張できるようにする。

---

## 9. 制約条件

### 技術的制約

- フロントエンド：TypeScript + Next.js
- バックエンド：Go
- データベース：PostgreSQL
- インフラ・ホスティング：未定（今後の検討事項）

### プロジェクト的制約

- 個人開発のため予算制約なし、明確な納期なし
- 「上手く作れたら日常利用したい」という前提があるため、実運用に耐えうる最低限の品質（データ消失なし、通知の正確な配信など）を意識する

---

## 10. 用語定義

| 用語       | 定義                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 在庫       | 家庭内に保有している食料品のこと                                                           |
| 期限       | 消費期限・賞味期限を区別せず統一的に扱う日付項目（任意入力）                               |
| 経過日数   | 期限未設定の食品について、購入日から現在までの経過日数                                     |
| カテゴリ   | 食品の種類分け（例：野菜、肉、乳製品など）。ユーザーがマスタ管理可能                       |
| 保管場所   | 食品を保管している場所（例：冷蔵庫、冷凍庫、パントリー、常温棚）。ユーザーがマスタ管理可能 |
| マスタ管理 | カテゴリ・保管場所など、システム全体で共通利用する分類データを管理する機能群の総称         |
